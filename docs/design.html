How data moves

  • Reads go through TanStack Query (a library that fetches, caches and refreshes server data), so counts and lists stay current without manual reloads.
  • Long work (a chat answer, a digest, a sweep) returns a job id at once; progress arrives over SSE (server-sent events, a one-way stream from the service to the page).
  • Writes are always two steps: propose → changeset, then apply with the note's base hash. If the note changed in between, apply refuses and asks you to re-run.
  • No state in the browser. Sessions, changesets and settings are notes in the vault, so reloading the page or switching PCs shows the same thing.
  • Secrets never reach the page. The Copy button asks the service to pipe Bitwarden output to the clipboard.
  • Opening in Obsidian uses an obsidian://open link (a URL that tells Obsidian which note to open).

    Extraction

    One capture, every note it yields

    Splitting a capture into the right notes is a core requirement, as important as losing nothing. One planner (app/extract.py) serves every entry point: paste into chat, Approve to digest, the Inbox and emails, and Sweep changes. The model proposes a typed split plan; code validates it and compiles it into a changeset.

    #StepAI?What it does
    1SegmentyesBreak the capture into atoms: one step, one explanation, one fact, one credential, one task, one general rule
    2ClassifyyesEach atom through the decision order (Handbook §3) and the topic folders (§2.3)
    3GeneralizeyesDoes this explanation hold beyond this case? Then it's a principle for a knowledge note; the specific case keeps only what's unique (§3.1 instance vs. principle)
    4Matchno, then yesExisting notes by title, alias, key, then search. Patch before create: a new section, collection rows, a History line
    5Plan—Atom → target note → operation → role (instance, principle, extracted), plus links both ways and to the MOC
    6VerifypartlyCorrections only with a cited source; anything unsupported goes in an Unverified box; origin: ai-chat stays
    7ValidatenoEvery atom lands in exactly one note; nothing lost across the set; no explanation duplicated; links resolve both ways; every note passes the invariants

    What the review card shows

    • The split map first: the capture on the left, the notes it produced on the right, one line per atom with its role and whether it's new or a patch.
    • Reassign or reject an atom before applying. The plan is typed data, so code recompiles it into operations with no second model call.
    • Per-note diffs follow, then the usual checks and Apply.
    • Pasted captures digest right away (Handbook §19.6), but the changeset still needs your approval, and nothing becomes solid knowledge without Approve to graduate.
    • Must not happen: everything filed under uv with no principle note (the first attempt's mistake), explanations duplicated into the SOP, a new uv note when one exists, the blog references treated as verified sources.

    The golden rule

    One handbook decides everything

    Where does a note go? First yes wins.

    1. Unprocessed or uncertain → 00-Inbox
    2. Something to do, find out or learn → task
    3. Still forming, no goal yet → idea
    4. An effort with an end → project
    5. An ongoing responsibility → area
    6. Steps to reproduce an outcome → SOP
    7. Login or access info → credential
    8. A single value to look up → fact
    9. A pointer to something external → resource
    10. An explanation, snippet or fix → knowledge
    11. None of the above → back to inbox, flagged for you

    Shortened from 15 steps (Handbook §3). Every note must also pass six checks: one type, the right folder, required properties, a unique title, at least one link, and at most three folders deep.

    Every change is approved

    The assistant writes proposals. You accept them per item, or all mechanical fixes at once.

    Nothing is lost

    Before any proposal reaches you, code checks that every code block, URL, number, link and sentence of the original still exists.

    Your edits win

    If a note changes while a job runs, the result is thrown away. Notes edited in the last 30 minutes are left alone by the sweep, and the sweep only runs when you click it.

    Secrets stay out of the AI

    Passwords go from Bitwarden straight to the clipboard, and notes marked sensitive are never quoted in chat.

    Same file rules on every host

    • Names follow the strictest combination of Windows, macOS and Linux: no <>:"/\|?*, no reserved names like CON, and case-insensitive uniqueness even on Linux.
    • Unicode is normalized to NFC (the composed form; macOS may hand back the decomposed form NFD), so one name never exists twice.
    • Always UTF-8. Traditional-Chinese Windows otherwise defaults to Big5 (cp950), which would corrupt 中文 notes.
    • Each file keeps its line endings. Writes go to a temp file first and replace the original in one step; if Windows reports the file as locked, the write is retried.
    • Each install has its own machine_id, so WSL and Windows on one PC count as two machines.
