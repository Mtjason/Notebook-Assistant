  • OperationList with checkboxes

  • ChecksBar: preservation, links, invariants, base hash

How data moves

  • Reads go through TanStack Query (a library that fetches, caches and refreshes server data), so counts and lists stay current without manual reloads.
  • Long work (a chat answer, a digest, a sweep) returns a job id at once; progress arrives over SSE (server-sent events, a one-way stream from the service to the page).
  • Writes are always two steps: propose → changeset, then apply with the note's base hash. If the note changed in between, apply refuses and asks you to re-run.
  • No state in the browser. Sessions, changesets and settings are notes in the vault, so reloading the page or switching PCs shows the same thing.
  • Secrets never reach the page. The Copy button asks the service to pipe Bitwarden output to the clipboard.
  • Opening in Obsidian uses an obsidian://open link (a URL that tells Obsidian which note to open).
